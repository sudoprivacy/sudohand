# 迁移盘点的覆盖范围与缺口

复核日期：2026-10-01 · adb 基线：v0.51.1 / `c349d347251779357136685b6a698e3d2c59ce6d`。

**当前盘点足以启动迁移和安排优先级，尚不足以宣布完整替换或归档 adb。** 仓库搜索、接口目录、真实行为和下游交付是四个不同的验收对象，不能用同一个覆盖率代替。

后续已增加 [历史与行为盘点](history-audit.md)：305 个提交、107 个 tags 的索引，实际 parser／SDK／测试目录，以及 27 个迁移单元的 [行为矩阵](adb-behavior-matrix.json)。下文保留依赖补查当时的范围；新的 storage live 结果、历史撤回项和测试覆盖分析以该补充文档为准。

## 1. 这次补查做了什么

- 本地：146 个 Git 工作目录，检查 162,950 个选定的 tracked 文件；移除源码后缀和 2 MiB 大小限制，加入 `aidb` 命令／环境别名与已知传递依赖。重复 worktree 仍按远端仓库合并。
- 远端：重新扫描原有 123 个仓库的默认分支，120 个非空；不按源码后缀筛选，共检查 102,492 个文本文件，包含原先未选入的 Go、C/C++、proto、无后缀脚本等。
- 仍排除构建／依赖目录、会话缓存。远端排除识别出的二进制文件，以及 4 个超过 32 MiB 的文件；这 4 个经核对是驱动包／共享库和 GIF 资源。
- 人工复核新增候选：图片字节里的别名匹配属于误报；一个服务协议描述浏览器消费者使用它，属于反向服务关系，不能据此认定该服务依赖 adb。
- **未发现新的实际调用仓库。** 已登记的 23 个调用／分发方、6 个文档引用方不变。本次是对已知仓库集合的补查，没有声称枚举所有外部用户或所有远端分支。

机器可读摘要见 [coverage-audit.json](coverage-audit.json)。含受限仓库的逐文件证据保存在本地完整台账旁的 `supplement/` 目录中。

搜索仍不能证明依赖集合绝对完备：远端非默认分支、仅存在于部署机器上的包装器／任务、运行时拼接导入、未知传递依赖、未登记的外部用户，需要在各消费者切换前继续确认。远端通过 NUL／UTF-8 采样识别文本，旧编码文本可能漏检。首轮检查过常见目录里的忽略技能，本次 tracked 文件补查没有扩大这些未跟踪目录的范围。

## 2. adb 的接口比 61 个命令更大

固定版本源码声明了：

- `ai_dev_browser.__all__`：34 个顶层公开导出。
- `ai_dev_browser.core.__all__`：86 个公开导出，含工具函数、连接／启动辅助函数、类型与常量。
- `ai_dev_browser.pool.__all__`：10 个导出，涉及 Job、Worker、BrowserPool、状态与持久化。
- 包源码中出现 16 个 `AI_DEV_BROWSER_*` 配置名；消费方还约定了调用关联与结果 sidechannel 的环境变量。

这些集合有重叠，不能相加当作功能数量。声明列表见 [python-api-surface.json](python-api-surface.json)。列表也不穷尽 CDP 协议域、导出类的方法、子模块 API 或消费者使用的私有函数；这些需要从实际调用点继续展开。

## 3. 分项判断

| 面向 | 当前证据 | 尚缺什么才算覆盖 |
|---|---|---|
| 调用方范围 | 两轮本地／默认分支搜索，按运行、测试、分发、文档分类 | 每个活跃调用方确认维护状态、部署入口、版本锁定和负责人；逐条闭合传递依赖 |
| CLI 工具与参数 | 61 工具基线、名称／部分参数差异；原 parity PR 对齐旧版本 | 每个工具的参数、默认值、JSON、stdout/stderr、退出码、重试和版本差异均有记录 |
| 真实浏览器行为 | 39 次真实 CLI 调用发现拖拽、失败退出、视口、异常分类差异 | 对全部受支持的用户任务验证实际页面／文件结果，覆盖失败、取消、超时和清理 |
| Python SDK | 顶层／core／pool 导出目录；已识别深度对象与继承依赖 | 连接／Tab／CDP 事件生命周期、异步行为、私有调用与 monkeypatch 的去留；每个消费者有可行迁移路径 |
| Pool 与 profile | 已发现 Job／Worker／状态持久化及 ProfileManager | 并发、租用／释放、失败恢复、取消、重启、profile 隔离与回滚的真实任务 |
| 传输与运行目标 | Python 支持 CDP 和扩展；下游使用 Electron/CEF | 扩展发现、重连、OOPIF/srcdoc、目标切换，以及缺少 Browser 域的嵌入式目标验收 |
| 登录与 cookies | 登录、在线／离线 cookies、存储相关工具已列入 | 操作系统密钥存储／解密、已有 profile 复用、权限与失败路径，不能只验证空白 Chrome |
| 配置与状态 | 16 个包内配置名及消费者 sidechannel 约定 | 参数／环境变量优先级、workspace 端口与 tab 选择、代理、viewport、dialog、focus 状态逐项处理 |
| 输入与图像 | 表单和基础截图通过；拖拽差异已确认 | trusted input、OS click、人类化参数、缩放／截图元数据与模型图像限制的联动 |
| 文件产物 | PDF、录制、下载有明确缺口 | 文件内容、尺寸／单位、时长／帧、文件名冲突、中断清理和跨调用生命周期 |
| 发行与安装 | adb 的 PyPI、GitHub、扩展 ZIP、校验和已识别 | 新二进制／架构、扩展资源、浏览器发现、干净安装、升级／回退、许可证和来源记录 |
| 消费者真实任务 | 已为 23 个调用／分发方登记任务方向 | 逐仓 live 记录、CI／已跑过的 live tests、发布版本；模型选择工具需要真实 API key 的本地测试 |

表中的“已识别”表示有证据或已列入工作，不代表 Rust 已实现或已通过验收。本轮没有执行新的浏览器功能迁移，也没有把帮助文本、静态扫描或 fake backend 测试当作行为等价证明。

### 3.1 本轮新增的真实启动失败

在 Windows 上按默认配置运行 `cargo build --locked -p sudohand-cli` 可以编译成功，但生成的调试二进制执行 `suh --help` 和 `suh serve --help` 均发生栈溢出，退出码为 `0xc00000fd`。已在本次文档变更前的 main 基线 `99a7c75bb286ca5ab6bb9f5a4e0828c6c65f5ea5` 上独立构建并复现相同结果。

因此这是已复现的基线问题，不是本次说明文字变更导致的回归。本轮未确认根因，也未验证 release 构建；不能扩大结论为所有 Windows 构建均不可用。它应作为 M3 的启动／发行验收项处理，同时补上每个支持平台真实二进制的 `--help`、`describe` 和浏览器任务检查。此前对 PR #27 的 Chrome 运行记录属于另一代码基线，不覆盖当前 main 的这项失败。

## 4. “足够完整”的可执行门槛

M1 结束前，为每一项受支持能力建立以下记录；消费者使用的私有 API 也必须登记：

`能力/接口 → adb 固定版本源码 → sudohand 实现或明确替代方案 → 消费者 → 真实任务 → 测试代码 → 最近一次运行证据 → 负责人/状态`

当前未测试的单元明确记为“未验收”；有差异的单元记为“待修复”或“有意改变并已迁移消费者”。不得把“存在同名函数”“CI skip”“没有搜到更多引用”记为通过。

下一步先做两个风险最高的端到端试验：

1. **Grok SDK／pool：**从已有 profile 建立连接，完成真实作业和产物下载，再验证重启恢复／取消，决定改写消费者还是提供有限 binding/bridge。
2. **sudowork 集成：**从干净安装开始，让真实 agent 发现工具、操作页面、回传截图并在会话中显示，验证重启和后端回退。

这两个试验通过后，才有足够依据收敛兼容策略和工作量；最终替换／归档仍按迁移规划的 M2–M6 门槛执行。
